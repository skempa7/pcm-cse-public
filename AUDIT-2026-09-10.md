# Chat CSE focused audit — September 10, 2026

This was a builder audit of the running application and implementation, followed by targeted fixes. It is not an independent critic round or a new clinical-readiness certification.

## Ranked findings and fixes

1. **Reliability: public engine failure could leave later requests waiting forever.** Once the worker's ready promise had resolved, an error only cleared requests already in flight. Subsequent calls went to a failed worker. The runtime now remembers terminal failure, settles outstanding calls, and rejects later calls promptly with recovery instructions. Storage errors now replace the misleading saved-status banner. Failure injection verified both paths. No network/provider service was added.
2. **Evidence clarity: introductions appeared as checked clinical history.** The backend now exposes a display-only boolean based on the event's delivered facts/concepts. Record puts social acknowledgments in Communication; actual clinical history remains separate. Hidden fact IDs and grading concepts remain absent from the encounter payload. No ledger or grading rule changed.
3. **Evidence clarity: doorway text containing “vitals” was mislabeled and grouped with measurements.** Supplied doorway information, vital signs, and supplied results now have distinct Record labels. Unavailable/interrupted examinations are retained separately as actions without findings, never as normal results.
4. **Navigation: guided exam links used old display labels.** Renamed one-click tiles no longer reliably matched those searches. Guide now navigates by stable maneuver ID, and ordinary search also recognizes original labels. Opening a suggested examination still grants no evidence and performs nothing; clicking an action starts it.
5. **Usability: coached Guide stage buttons buried useful content.** The seven large stage cards become a compact focus selector, retaining the same coaching stages and on-demand hints. Guided practice keeps its case-specific step sequence; independent/rehearsal modes remain protected. The conversation has more room.
6. **Incorrect instructions: missed-moment retries promised the old timed behavior.** Text now accurately states that new guided/coached retries are untimed and preserve the original attempt's timing and score.
7. **Maintenance: stale private standalone package.** Rebuilt `dist/pcm-cse.html` from current sources and verified its case-library stamp. The existing server app and public browser engine remain the primary current 3D experience.
8. **Small cleanup:** clear pending feedback-dismissal timers when leaving an encounter, hide empty secondary Record groups, improve disabled/focused exam-button states, and replace obsolete “review selections” wording with position/technique guidance.

- **72 public case/variant paths passed** doorway → encounter → organization → note → submission/locked original, plus public provider-route rejection and asset/package checks.
- **3,196 authored example dialogue turns across all 72 paths** returned their expected fact IDs. This is automated consistency checking, not a clinician reviewing all the wording, reasoning, or plans.
- Conversation-specific regression checks passed across **72 variants**; four learning-mode timing checks passed.
- **82 examination tiles** checked for valid component selections and conflicting posture/quadrant combinations.
- New Record test passed in both editions: social greeting versus clinical opening, separate supplied categories, no hidden fact identifiers, no ledger mutation.
- Runtime failure injection: storage error shown; in-flight request settled after crash; subsequent request failed promptly; external-provider fetch rejected.
- Actual isolated Chrome interactions: coached male encounter and guided female encounter; introduction/opening; Guide draft-to-chat; guided exam link; one-click general inspection; Record; reload; seated, standing, supine, and prone controls; reduced motion; expanded/split view; full-patient preset; SOAP draft save/reload; submission and feedback; duplicate public-tab guard. - Layout: no horizontal or page-height overflow at **1366×768, 1280×720, and 1093×614**. At **390×844**, the interface stacks and scrolls with no horizontal overflow. Changing viewport size is a responsive-layout test, not direct verification of macOS trackpad pinch or native browser zoom gestures.

## Limits and remaining work

- The historical full suite is still not green: obsolete expectations and extracted-function test harnesses need maintenance. They were not silently deleted, weakened, or counted as passing. The targeted current-behavior suite passed.
- Existing provisional SOAP grading limitations remain. Do not interpret this audit as validating all possible free-text notes or all clinical teaching. Existing development-status notices remain.
- No paid AI or natural-voice calls were made. Provider logic was tested with local mocks; audible device-voice quality, exact macOS voice matching, and live paid speech were not revalidated here.
- Position controls were operated, but this audit did not redo detailed mesh/contact or motion-quality review for every body type. No patient/room geometry was changed.
- Worker failure was injected at the runtime boundary; this did not physically fill the browser's storage quota or crash the operating system.
- Existing third-party room license limitations in the notices remain; this audit does not provide new redistribution permission.

## Reproduction and retained evidence

Public: open the Guide in a coached encounter; select its focus. In guided practice, choose Steps → a heart examination → Open this examination. One matching heart action should appear, without any examination event until clicked. Introduce yourself and inspect Record: the greeting should be in Communication. Actual answers appear in History obtained. Finish, write a short note, wait for saving, reload, and submit.

Run `python3 tools/test_audit_record.py` in either checkout and `node tools/test_runtime_recovery.cjs` in the public checkout. Existing case-path verification is `python3 tools/test_public_release.py` in the public checkout.
